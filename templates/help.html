✨ 功能介绍

DockerConverter 是一款高效的在线工具，可以将传统的 docker run 命令批量转换为现代的 docker-compose.yml 格式。 支持 Web UI 和命令行两种使用方式，满足不同场景的需求。

🔄

批量转换

支持一次性输入多条 docker run 命令，自动识别并批量转换为 docker-compose.yml 格式，大幅提升工作效率。

👁️

实时预览

输入命令后立即看到转换结果，支持语法高亮显示的 YAML 输出，方便检查和修改。

📚

参数丰富

支持 50+ 种 docker run 参数，包括网络、存储、资源限制、健康检查等常见配置。

💾

历史记录

登录后可保存转换历史，支持查看、复制和重新编辑，方便管理多个项目的配置。

📤

文件上传

支持上传 .txt 文件批量处理，可以先在编辑器中编写好命令，再统一转换。

🎨

主题美观

采用现代化的深色主题设计，界面简洁美观，支持响应式布局，适配各种设备。

🚀 快速开始

只需三步，即可完成 docker run 到 docker-compose.yml 的转换。

1

粘贴命令

在左侧输入框中粘贴您的 docker run 命令。支持多条命令、多行续行（\）和注释（#）。

docker run -d \ --name my-nginx \ -p 80:80 \ -v ./html:/usr/share/nginx/html:ro \ --restart unless-stopped \ nginx:latest
2

点击转换

点击"⚡ 转换"按钮，或使用快捷键 Ctrl + Enter，即可实时生成 docker-compose.yml。

💡

小提示

可以点击"示例"按钮加载内置的示例命令，了解支持的参数格式。

3

复制或下载

转换完成后，可以一键复制 YAML 内容，或下载为 docker-compose.yml 文件。

# 查看转换结果 services: my-nginx: image: nginx:latest container_name: my-nginx ports: - "80:80" volumes: - ./html:/usr/share/nginx/html:ro restart: unless-stopped

🔧 支持的参数

DockerConverter 支持将大多数常用的 docker run 参数转换为 docker-compose 格式。以下是主要支持的参数列表：

docker run 参数 docker-compose 字段 说明
--name container_name 容器名称
-p / --publish ports 端口映射
-v / --volume volumes 数据卷挂载
-e / --env environment 环境变量
--restart restart 重启策略
--network networks 网络配置
--hostname hostname 主机名
--add-host extra_hosts 额外hosts映射
--privileged privileged: true 特权模式
--read-only read_only: true 只读根文件系统
-t / --tty tty: true 分配伪终端
-i / --interactive stdin_open: true 保持标准输入打开
--cpus / -m deploy.resources.limits CPU和内存限制
--health-* healthcheck 健康检查配置
--dns / --dns-search dns / dns_search DNS配置
--cap-add / --cap-drop cap_add / cap_drop Linux capabilities
--gpus deploy.resources.reservations GPU配置
--user user 运行用户
--working-dir / -w working_dir 工作目录
--label labels 容器标签
⚠️

注意事项

部分参数（如 --pull、--detach、--rm 等）在 docker-compose 中有默认行为或不支持， 这些参数会被自动忽略。部分复杂参数（如 mount、volumes-from 等）目前尚未支持。

📝 使用示例

下面是一些常见使用场景的完整示例，展示了如何将复杂的 docker run 命令转换为 docker-compose.yml。

📦

完整的Web服务配置

包含端口、环境变量、卷挂载、健康检查等完整配置：

# 输入命令 docker run -d \ --name my-webapp \ -p 8080:80 \ -e APP_ENV=production \ -e DB_HOST=db.example.com \ -v ./data:/var/www/data \ -v ./logs:/var/log/nginx \ --network app-net \ --network-alias webapp \ --restart always \ --health-cmd "curl -f http://localhost/health || exit 1" \ --health-interval 30s \ --health-timeout 10s \ --health-retries 3 \ --memory 512m \ --cpus 0.5 \ nginx:alpine
🗄️

数据库服务配置

数据库服务通常需要持久化存储和安全配置：

# 输入命令 docker run -d \ --name postgres-db \ -p 5432:5432 \ -e POSTGRES_USER=admin \ -e POSTGRES_PASSWORD=secret123 \ -e POSTGRES_DB=myapp \ -v postgres-data:/var/lib/postgresql/data \ --network app-net \ --restart always \ --health-cmd "pg_isready -U admin" \ --health-interval 10s \ --health-timeout 5s \ --health-retries 5 \ postgres:15-alpine
🤖

后台Worker服务

后台任务服务通常不需要端口映射，但需要资源限制：

# 输入命令 docker run -d \ --name my-worker \ --network app-net \ --add-host host.docker.internal:host-gateway \ -e REDIS_HOST=redis.example.com \ -e QUEUE_NAME=tasks \ -v ./worker-logs:/app/logs \ --restart unless-stopped \ --memory 1g \ --cpus 1 \ --user 1000:1000 \ myorg/worker:v2.0

❓ 常见问题

关于 DockerConverter 的常见问题及解答。

为什么转换后的 YAML 有些参数不完整？ +

部分 docker run 参数在 docker-compose 中没有直接的对应配置，或者需要额外的手动调整。 这些参数会在转换时给出警告提示。建议仔细检查生成的 YAML，并根据实际情况进行补充修改。 如果遇到不支持的参数，欢迎在 GitHub 上提交 Issue。

支持 docker compose 命令吗？ +

目前 DockerConverter 主要支持 docker run 命令的转换。如果您的命令已经是 docker-compose 格式， 或者需要从现有的 compose 文件中提取 run 命令，则不需要使用此工具。未来的版本可能会增加更多功能支持。

网络配置有什么需要注意的？ +

使用 --network 参数指定的网络会自动在 compose 文件中声明为外部网络（external: true）。 如果您希望使用内部网络，需要手动修改 compose 文件中的网络配置。另外，如果多个服务使用同一个网络， 确保它们的服务名和网络配置都正确。

如何处理敏感信息？ +

建议使用 --env-file 参数从环境变量文件中读取敏感配置，而不是直接在命令行中明文传递密码。 转换后的 compose 文件中，敏感信息可以通过 Docker Secrets 或环境变量文件来管理， 而不是直接写在 YAML 中。

转换后的文件可以直接使用吗？ +

大多数情况下，转换后的 docker-compose.yml 可以直接使用。但在生产环境中，建议： 1) 检查所有配置是否符合预期；2) 使用环境变量替代硬编码的敏感信息； 3) 根据实际需求调整网络、存储等配置；4) 在测试环境中验证后再部署到生产。

如何获取命令行版本？ +

DockerConverter 同时提供命令行工具。在项目根目录执行 python DockerConverter.py 即可使用 CLI 模式。CLI 模式会读取 samples/docker_commands.txt 文件中的命令， 并输出转换结果到 docker-compose.yml 文件。

--rm 参数如何处理？ +

--rm 参数在 Docker Compose 中没有直接的对应配置。这个参数用于在 docker run 时让容器在退出后自动删除。

在 Docker Compose 中，容器默认不会在退出时自动删除。如果您需要类似的行为：

  • 使用 docker compose up 启动后，使用 docker compose down 可以删除所有相关资源
  • 使用 docker compose run --rm service_name 可以在一次性运行命令时自动清理
  • 对于需要定期清理的场景，可以在 Compose 文件中通过其他机制（如健康检查 + 脚本）来处理

DockerConverter 在转换时会检测到 --rm 参数并给出警告，但不会影响其他参数的转换。
